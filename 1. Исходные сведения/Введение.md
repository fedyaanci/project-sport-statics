# Введение

## Цель проекта

«Спортивная статистика» — веб-приложение для сбора и анализа данных спортивных матчей. В нём можно записывать игровые действия, получать показатели команд и игроков, смотреть результаты и готовить материалы по итогам игр.

В этой работе описаны требования к приложению. Они понадобятся при выборе архитектуры и разработке. Основой стали задание проекта, Event Storming и User Story Map.

## Пользователи

| Пользователь | Что ему нужно |
|---|---|
| Аналитик | Сравнивать команды перед матчем |
| Тренер | Подавать состав, оценивать игроков и готовить отчёт спонсорам |
| Игрок | Смотреть свои достижения, видео и прогресс за несколько сезонов |
| Фанат | Смотреть табло, сравнивать игроков и создавать инфографику |
| Журналист | Писать обзоры и делать прогнозы |
| Организатор | Готовить соревнование и подтверждать результаты |
| Оператор | Записывать и исправлять игровые действия |
| Администратор | Выдавать и отзывать рабочие права |
| Редактор видео | Добавлять видео и связывать фрагменты с действиями |

Один человек может иметь несколько ролей. При этом права действуют только для назначенного турнира, команды или матча. Обычная регистрация не даёт права менять результаты.

## Как работает приложение

Организатор открывает сезон, допускает команды и игроков, назначает матчи. Тренер подаёт состав, а организатор его подтверждает.

Во время игры оператор записывает действия. Из них рассчитываются предварительные показатели и счёт на табло. После завершения матча сохраняется итоговый протокол. Организатор проверяет его и подтверждает результат. Затем публикуется официальная версия.

Другие пользователи читают статистику, сравнивают участников, смотрят видео и создают материалы. Для отчёта, инфографики и прогноза сохраняются черновик, готовый результат и опубликованная версия.

Если оператор исправляет действие, прежнее значение остаётся в истории. Повтор одного запроса не должен засчитывать второй гол. Ошибка ввода не должна менять счёт.

## Релизы

| Версия | Что входит |
|---|---|
| MVP | Вход, права, сезон, участники, составы, проведение матча, протокол, статистика и онлайн-табло |
| Первый релиз | Сравнения, анализ позиции и прогресса, видео, обзоры, отчёты, инфографика и архив |
| Второй релиз | Прогнозирование, импорт, несколько спортивных регламентов и восстановление рабочей копии архива |

Каждая следующая версия включает предыдущую. Такое деление соответствует User Story Map: 28 историй в MVP, 62 после первого релиза и 70 после второго.

## Границы проекта

В приложении не будет продажи билетов, платежей, ставок и медицинских данных. Пользователи работают через браузер.

Публикация отчёта или инфографики означает размещение внутри сервиса. Автоматическая отправка в соцсети или письмом адресату в эти функции не входит.

Для учебной демонстрации используются вымышленные профили и разрешённые видеозаписи. Перед работой с реальными данными нужно отдельно определить правила доступа, хранения и публикации.

## Технические условия

Проект разрабатывается одним человеком. Основной язык — Python, база данных — SQL. Для первой версии предлагаются Django и PostgreSQL. Интерфейс можно сделать обычными HTML-шаблонами с CSS и небольшим JavaScript для табло.

Сначала поддерживается один согласованный вид спорта. Несколько регламентов добавляются во втором релизе. Формулы показателей и правила действий нужно определить до программирования соответствующих функций.

Для пилота принят небольшой профиль нагрузки: 20 читателей табло и 2 оператора. Числа в требованиях — цели для проверки будущей программы. Измерения пока не проводились.
