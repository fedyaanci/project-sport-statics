# L2: Контейнеры

![Диаграмма контейнеров](<../out/2. Технический проект/Контейнеры.svg>)

[Исходник](Контейнеры.puml) · [PNG](<../out/2. Технический проект/Контейнеры.png>)

Контейнер в C4 — выполняемое приложение или хранилище. Веб-приложение и фоновые процессы используют один Python-проект и выпускаются вместе. HTML-шаблоны относятся к Django-приложению.

## Части системы

| Контейнер | Назначение |
|---|---|
| Веб-приложение | Принимает формы, проверяет права и бизнес-правила, возвращает HTML и JSON |
| База данных | Одна PostgreSQL для аккаунтов, соревнований, действий, протоколов, заданий и истории |
| Обработчик писем и материалов | В MVP отправляет почту; с R1 создаёт отчёты и инфографику; с R2 считает прогнозы |
| Обработчик видео | С R1 запускает FFmpeg отдельно от обработки писем и материалов |
| Файлы материалов | Закрытый каталог для видео, фрагментов, HTML-отчётов и изображений |
| Служебные команды | Команды того же проекта, которые запускает планировщик ОС: проверка работоспособности и резервирование |
| Резервные копии | Семь исправных комплектов БД и файлов вне основного диска |

Для инфографики используется Matplotlib, для видео — FFmpeg. Прогноз рассчитывается на Python и SQL по сохранённому срезу и версии методики. Эти инструменты работают внутри обработчиков.

## Взаимодействие

| Связь | Данные и протокол |
|---|---|
| Браузер → Django | Формы и HTML по HTTPS; табло получает JSON примерно раз в секунду |
| Django и обработчики → PostgreSQL | SQL через Psycopg 3 по TCP; чтение, запись и транзакции |
| Django → внешний источник | С R2 получение JSON-пакета по HTTPS через адаптер поставщика |
| Обработчик писем → почтовый сервис | SMTP с TLS; сохраняются номер попытки и результат передачи |
| Приложение и обработчики → файлы | Локальный файловый API ОС; пользователь получает файл через проверку доступа в Django |
| Служебные команды → приложение и БД | Проверка раз в минуту; уведомление об отказе в пределах пяти минут |
| Служебные команды → резервные копии | Ежедневный дамп `pg_dump`, копия файлов и проверка состава |

Для внешнего источника выбран транспорт HTTPS/JSON. Конкретный поставщик и его поля выбираются при реализации R2. Адаптер переводит его формат во внутренний пакет, поэтому остальные модули не зависят от названий полей поставщика.

## Задания и готовые файлы

Веб-приложение сохраняет объект и задание одной транзакцией. Обработчик забирает задание из БД, отмечает попытку и выполняет работу без долгой блокировки транзакции. Перед сохранением проверяет, что попытка и версия черновика ещё актуальны.

Сначала создаётся и проверяется файл, затем в БД фиксируется готовность. Повтор открывает сохранённый результат. Новая обработка создаёт попытку того же объекта. Ошибки и состояния остаются после перезапуска.

Видеопроцесс имеет ограничение ресурсов. Если при обработке не выполняются требования ко времени ввода и отчётов, тяжёлая работа переносится за пределы матча.

## Табло и обслуживание

Табло читает одну сохранённую версию показателей без кэша ответа. Одновременные запросы одной вкладки не накладываются. При обрыве связи остаются последние данные с предупреждением и временем обновления. Цель — показать действие за три секунды при 20 зрителях и двух операторах.

Проверка доступности запускается на отдельном постоянно работающем узле, чтобы заметить остановку основного сервера. Она обращается к `/health`, который проверяет также БД; прямой доступ к PostgreSQL ей не нужен. Команда резервирования запускается на сервере данных. На L2 эти служебные команды одного проекта объединены по назначению; их размещение относится к развёртыванию.

Резервирование временно приостанавливает запись и фоновые изменения, дожидается текущих операций, копирует БД и файлы, проверяет комплект и возобновляет работу. Пауза входит в допустимый простой 1% в месяц. Ручное восстановление должно занимать до четырёх часов при потере не более суток изменений.

Архив сезона сохраняет бизнес-историю и читается приложением. Резервная копия нужна для восстановления после технического сбоя.

Основание: ADR 01–09, 11; PER01–PER07, SCA02–SCA04, AVA01–AVA04, DUR01–DUR08, MON01–MON04. Следующий уровень — [компоненты веб-приложения](Компоненты.md).
